Towk uses separate delivery paths for each client:

- Android receives an encrypted wake signal through the managed FCM relay, then fetches the notification from your Towk instance.
- Linux keeps an authenticated WebSocket open while the application is running. Closing the application stops Linux notifications; minimizing it does not.
- Browsers and installed PWAs use Web Push and VAPID. Configure that path separately.

The managed relay does not receive message text, room names, session tokens, or your instance's private notification keys. Self-hosters do not need a Firebase service-account key: the Android application already contains the public Firebase client metadata required to reach the shared relay.

## Prerequisites

- a public Towk URL served over HTTPS;
- durable storage writable by the Towk process for the instance identity and enrollment state;
- outbound HTTPS access to the relay URL supplied by the Towk project;
- a deployed Towk binary and Android client from compatible releases.

## Configure the instance

Create a private state directory owned by the Towk service account. The two JSON files below are generated by Towk; do not create, publish, or bake them into an image.

```bash
install -d -m 0700 -o towk -g towk /var/lib/towk/native-notifications
```

Set the following environment variables on the Towk server. Replace the relay hostname with the public managed-relay URL distributed with the Android client.

```bash
CHATTO_NATIVE_NOTIFICATIONS_ENABLED=true
CHATTO_NATIVE_NOTIFICATIONS_SHADOW_OUTBOX=true
CHATTO_NATIVE_NOTIFICATIONS_ANDROID_MANAGED_FCM=true
CHATTO_NATIVE_NOTIFICATIONS_LINUX_RESIDENT_WEBSOCKET=true
CHATTO_NATIVE_NOTIFICATIONS_MANAGED_FCM_RELAY_URL=https://relay.example.net
CHATTO_NATIVE_NOTIFICATIONS_IDENTITY_FILE=/var/lib/towk/native-notifications/identity.json
CHATTO_NATIVE_NOTIFICATIONS_ENROLLMENT_STATE_FILE=/var/lib/towk/native-notifications/enrollment.json
```

Both state paths must be absolute and stored on a persistent volume. Keep their directory mode at `0700`; the files contain the instance identity and relay enrollment state.

## Enroll and start

<Steps>

1. Run enrollment once with the same configuration and environment as the Towk service:

   ```bash
   towk native-notifications enroll --config /etc/towk/towk.toml
   ```

2. Confirm that the command reports an instance ID and the expected relay URL. Enrollment also verifies that the configured public Towk URL is reachable over HTTPS.

3. Restart the Towk service. A successful startup reports that managed FCM delivery is enabled. If enrollment is missing, Towk keeps serving its proof endpoint but does not start the FCM delivery worker.

4. Sign in from Android and Linux. Android registers its FCM installation automatically; Linux registers a resident WebSocket while the application is running.

</Steps>

Do not run enrollment on every container start. Reuse the durable identity and enrollment files. Losing them creates a different relay identity and requires re-enrollment.

## Validate delivery

Use only test accounts and a private room. Verify at least:

1. a direct message;
2. a normal room message with the room preference set to **All messages**;
3. a mention;
4. a reply to a message authored by the recipient;
5. an incoming call notification.

For Android, repeat one test with Wi-Fi and mobile data disabled, then restore connectivity. The queued FCM wake signal must result in a notification after the device reconnects. Do not use Android **Force stop** as an offline test: Android intentionally blocks FCM delivery to force-stopped applications.

For Linux, minimize the application and repeat the matrix. Notifications are expected while the process is alive, not after it has exited.

## Rotation and recovery

- Back up the two native-notification state files with the rest of the Towk service state.
- Restore both files together. Do not copy one instance identity across several independent Towk installations.
- If either file is lost or intentionally rotated, stop the Towk service, remove only the affected enrollment pair, enroll again, and restart.
- Never place a Firebase service-account credential in the Towk server, Android repository, container image, or public documentation.
